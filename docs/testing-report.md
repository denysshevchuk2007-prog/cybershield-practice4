# Звіт перевірки CyberShield

## Автоматизовані сценарії

Набір `tests/test_api.py` перевіряє:

1. Коректне надсилання форми, запис у SQLite та збереження запису після перезапуску HTTP-сервера.
2. Відмову сервера для некоректного імені, email і короткого повідомлення.
3. Відмову в перегляді без автентифікації та успішний перегляд/видалення після входу.
4. Відповіді головної та адміністративної сторінок.

GitHub Actions запускає їх командою `python -m unittest discover -s tests -v`.

Фактичний локальний прогін: Python 3.15.1, 4 тести — OK. Перевірено HTTP-відповіді обох сторінок і локальних ресурсів, валідне/невалідне надсилання, сесійну автентифікацію, видалення та відновлення запису після повторного запуску тестового HTTP-сервера. JavaScript-файли пройшли перевірку синтаксису.

## Ручні сценарії для локального браузера

Запустіть сервер і перевірте домашню сторінку, якірні посилання, зміну теми, мобільне меню, розгортання тексту, додавання/видалення картки, форму з порожніми й некоректними значеннями, успішне збереження, вхід до `/messages`, видалення запису та збереження після перезапуску.

Статичний огляд стилів підтвердив наявність мобільного (600 px) та tablet/menu (900 px) breakpoint. Візуальну перевірку при ширині 375 px, 768 px і 1440 px ще треба виконати в Chrome та записати результат.

## Lighthouse

Фактичні оцінки й знімок Lighthouse потрібно додати після запуску аналізу в Chrome DevTools на локальному сервері. Не вказуйте оцінки без виконаного вимірювання.

| Режим | Performance | Accessibility | Best Practices | SEO |
| --- | --- | --- | --- | --- |
| Mobile | заповнити за звітом | заповнити | заповнити | заповнити |
| Desktop | заповнити за звітом | заповнити | заповнити | заповнити |

Поточні оптимізації: немає зовнішніх JavaScript-бібліотек і растрових зображень; CSS-ілюстрації; прибраний зовнішній вебшрифт; Fetch API без повного перезавантаження сторінки.

## Виявлені та виправлені проблеми

- Відсутність серверної перевірки виправлена незалежною перевіркою обов’язкових полів і email.
- Доступ до API читання/видалення обмежений сесією адміністратора.
- SQL із введеними значеннями використовує параметризовані запити.
- Форма працює через Fetch API й показує помилки/успіх без навігації сторінки.
- Секретний пароль адміністратора не зберігається у файлах проєкту; його треба задавати змінною середовища.
- Перший прогін виявив незакриті з'єднання SQLite, які блокували прибирання тестової бази у Windows; додано гарантоване закриття з'єднань, повторний прогін усіх 4 тестів пройшов.
- Консоль показувала відсутній `/favicon.ico`; додано локальні ICO та SVG-іконки, сервер віддає обидві зі статусом HTTP 200, а тест перевіряє їх наявність.

## Результати прогону

Заповнити після запуску `py -m unittest discover -s tests -v` і ручних перевірок. Додати знімки форми, підтвердження збереження, сторінки повідомлень і звіту Lighthouse до матеріалів здачі.
